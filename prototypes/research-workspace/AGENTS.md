# Agent Instructions: Research Workspace

## What This Prototype Demonstrates

A multi-user research platform combining a public gallery (browse published insights, syntheses, architecture diagrams) with an authenticated workspace (markdown editor, file browser, xterm.js terminal). Content is generated by Cloud Scheduled Tasks running Claude Code against arXiv papers based on user-set "learning intentions."

**Live**: `portfolio.cookinupideas.com/prototypes/research-workspace/`

## Architecture

```
CloudFront (E25WB0ZPQ7JJFT)
├── /prototypes/research-workspace/vault*  →  ALB → Cognito → ECS (Express.js)
│   ├── /api/vault/tree                    →  File listing (EFS)
│   ├── /api/vault/files/*                 →  File CRUD (EFS)
│   ├── /api/vault/links                   →  Wiki-link graph
│   ├── /api/vault/terminal                →  WebSocket (xterm.js ↔ node-pty)
│   └── /healthz                           →  Health check
│
├── /prototypes/research-workspace/*       →  S3 (gallery SPA)
│   ├── /                                  →  Public gallery
│   ├── /content/:id                       →  Content detail
│   └── /workspace                         →  Authenticated workspace SPA
│
├── /api/v1/research-workspace/*           →  API Gateway → Lambda
│   ├── /published                         →  DynamoDB (public content)
│   ├── /intentions                        →  DynamoDB (auth'd)
│   └── /feedback                          →  DynamoDB (auth'd)
│
└── /oauth2/*                              →  ALB → Cognito callback
```

**Two SPAs, one build:** The gallery and workspace are client-side routes in the same React app. The gallery is public (served from S3). The workspace makes API calls to the vault backend (ECS) which requires Cognito auth via the ALB.

## Deployment — COMPLETE CHECKLIST

Deploying this prototype has **four layers** that must all be correct. A partial deploy will fail silently (the old container keeps running, health checks pass on the wrong image, etc.). Follow this checklist in order.

### Prerequisites
```bash
# Assume IAM role (required for ALL AWS operations)
eval $(aws sts assume-role --role-arn "arn:aws:iam::671388079324:role/terraform-cooking-up-ideas" \
  --role-session-name "deploy-session" --output json \
  | python3 -c "import json,sys;c=json.load(sys.stdin)['Credentials'];print(f'export AWS_ACCESS_KEY_ID={c[\"AccessKeyId\"]} AWS_SECRET_ACCESS_KEY={c[\"SecretAccessKey\"]} AWS_SESSION_TOKEN={c[\"SessionToken\"]}')")
```

**CRITICAL: The IAM role credentials do NOT persist between separate shell commands.** Each command in a new shell must re-assume the role. Chain commands with `&&` in a single shell invocation, or use `eval` + `&&` together.

### Layer 1: Docker Image → ECR
```bash
cd apps/research-workspace
docker build -t research-workspace .
docker tag research-workspace:latest 671388079324.dkr.ecr.us-east-1.amazonaws.com/research-workspace-prod:latest
aws ecr get-login-password --region us-east-1 | docker login --username AWS --password-stdin 671388079324.dkr.ecr.us-east-1.amazonaws.com
docker push 671388079324.dkr.ecr.us-east-1.amazonaws.com/research-workspace-prod:latest
```
ARM64 native — do NOT add `--platform linux/amd64`.

### Layer 2: Terraform (CloudFront + ECS task definition + target group)
```bash
cd terraform
terraform apply -auto-approve \
  -var="github_oauth_client_id=Ov23limPUjSbaPOZ4PFW" \
  -var="github_oauth_client_secret=<secret>"
```
**The GitHub OAuth vars are required** — without them, Terraform destroys the Cognito identity provider and breaks authentication. They are NOT in `terraform.tfvars`. If you only need CloudFront changes, target specifically: `-target=aws_cloudfront_distribution.website`.

### Layer 3: Force ECS Redeployment
```bash
LATEST_TD=$(aws ecs describe-task-definition --task-definition research-workspace-prod \
  --region us-east-1 --query 'taskDefinition.taskDefinitionArn' --output text)
aws ecs update-service --cluster ai-testing-resource-prod --service research-workspace-prod \
  --task-definition "$LATEST_TD" --force-new-deployment --region us-east-1
```
**WHY THIS IS NEEDED:** The ECS service has `lifecycle { ignore_changes = [task_definition] }` in Terraform. This means `terraform apply` creates new task definition revisions but NEVER updates the running service to use them. You MUST manually `update-service` with the new task definition ARN and `--force-new-deployment` to pull the new image.

### Layer 4: SPA → S3 + CDN Invalidation
```bash
cd /path/to/repo
./scripts/build.sh
aws s3 sync dist/ s3://portfolio-portal-code --delete --exclude "*.map"
aws cloudfront create-invalidation --distribution-id E25WB0ZPQ7JJFT --paths "/*"
```

## Gotchas

### Path Prefix Stripping
The ALB forwards the FULL CloudFront path to the container (e.g., `/prototypes/research-workspace/vault/api/vault/tree`). The Express server strips the `/prototypes/research-workspace/vault` prefix via middleware so routes match (`/api/vault/tree`). This also applies to WebSocket upgrade requests. **If you add routes, use the short path (e.g., `/api/vault/new-route`), not the full CloudFront path.**

### CloudFront Path Pattern
The vault behavior uses `vault*` (no slash before `*`). This matches `/vault`, `/vault/`, and `/vault/anything`. The previous `vault/*` pattern did NOT match `/vault` (no trailing slash), causing a 404 by falling through to the S3 gallery behavior.

### ECS `ignore_changes` Trap
Terraform will show "No changes" even when the task definition config has changed, if the ECS service already has `ignore_changes = [task_definition]`. Always check: did you push a new image? Did you force-deploy the service? "Terraform applied successfully" does NOT mean the container is running your latest code.

### Cognito OAuth Variables
`terraform apply` without `-var="github_oauth_client_id=..."` will DESTROY the GitHub identity provider (`count = var.github_oauth_client_id != "" ? 1 : 0` defaults to 0). This breaks all authentication. Always pass these vars or use `-target` to limit the apply scope.

### Content files
Gallery content (`data/` and `content/` dirs) is fetched at runtime from S3, not bundled. The research loop writes directly to these paths.
